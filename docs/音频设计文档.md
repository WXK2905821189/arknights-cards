# 罗德岛棋局 · 音频系统设计文档

> 设计：游戏音频工程师（Game Audio Engineer）
> 适用：纯静态、可离线、双击即玩的网页自走棋（货币战争）
> 配套实现：`audio.js`（事件驱动引擎，无外部依赖，已接入 `game.js` / `game.html`）

---

## 1. 设计目标与现状差距

### 1.1 现状
- `sfx.js`：纯振荡器合成，9 个硬编码 blip（click / select / buy / reroll / error / node / win / lose / boss）。
- 无音乐系统、无事件总线、无参数驱动、无语音管理、无混音总线。
- 游戏逻辑里直接 `SFX.play(name)`，没有"状态 → 音频"的映射层。

### 1.2 目标（专业中间件规范在 Web 上的适配）
| 维度 | 旧 | 新 |
|---|---|---|
| 触发方式 | 散落 `SFX.play` | 命名事件 `AUDIO.play(event, params)`，游戏不直接造声 |
| 音乐 | 无 | 自适应生成式音乐，由 `tension` 参数驱动 |
| 混音 | 单路 | 主总线 + 压缩 + `music/sfx/ui` 三路总线 |
| 语音管理 | 无上限 | 24 路并发上限 + 优先级抢占（steal） |
| 参数 | 无 | 伤害类型、阵营、技能 archetype、战斗强度全部走参数 |
| 资源 | 纯合成 | 合成兜底；预留接口替换为真·采样/分层音乐 |

## 2. 声音身份（Sonic Identity）

用三个形容词定义本作应该如何"听"起来：

1. **冷峻（Austere）** —— 工业感、克制、理性的军事基调配色，避免卡通化。
2. **工业（Industrial）** —— 低频脉冲、金属质感、噪声纹理，呼应罗德岛舰船与源石科技。
3. **希望（Resolute）** —— A 小调进行中埋伏大调色彩（i–VI–III–VII），在战斗紧张里保留坚定感。

> 音乐和弦：Am – F – C – G（A 小调，冷峻但带希望），程序化生成，可整体替换为分轨素材。

## 4. 事件命名规范（对齐 FMOD/Wwise）

```
event:/[Category]/[Subcategory]/[EventName]
```

| 类别 | 总线 | 示例 |
|---|---|---|
| `ui` | ui（最高优先，永不被抢占） | `ui/click` `ui/select` `ui/open` `ui/close` `ui/error` |
| `shop` | sfx | `shop/buy` `shop/reroll` `shop/levelup` `shop/sell` `shop/insufficient` |
| `deploy` | sfx | `deploy/place` `deploy/pickup` `deploy/invalid` |
| `combat` | sfx | `combat/hit` `combat/skill` `combat/heal` `combat/shield` `combat/summon` `combat/death` `combat/burn` |
| `strategic` | sfx | `strategic/node_enter` `strategic/bond_unlock` `strategic/strategy_pick` `strategic/encounter_pick` `strategic/promote` |
| 结算 | music | `result/win` `result/lose` `result/boss`（经音乐总线的一次性 stinger） |

**向后兼容**：`window.SFX.play('click'|'select'|'buy'|'reroll'|'error'|'node'|'win'|'lose'|'boss')` 仍可用，自动映射到新事件。

## 5. 混音与语音架构

```
                  ┌────────────┐
  各事件 ───────► │  music bus │ ─┐
  (程序化合成)    ├────────────┤  │
                  │  sfx   bus │ ─┤──► master gain ──► DynamicsCompressor ──► destination
                  ├────────────┤  │     (0.9)          (防止削波 -18dB/4:1)
                  │  ui    bus │ ─┘
                  └────────────┘
```

- **主总线压缩**：threshold −18dB / ratio 4 / attack 3ms / release 250ms，作为混音保险，杜绝总线削波。
- **音乐总线**：基准增益 0.5；状态切换走 0.8s 线性交叉淡入（无硬切）。
- **语音管理（voice budget）**：SFX 并发上限 **24 路**；超出时按优先级抢占最低优先级语音。
  - 优先级：UI/结算 = 0（永不被抢）；商店/部署/战略 = 1；战斗 = 2。

### 网页音频预算（Audio Performance Budget）
| 项 | 规格 |
|---|---|
| 采样率 | 44100 Hz（Web 默认） |
| SFX 并发语音 | 24（移动端可下调至 16） |
| 音乐生成语音 | 程序化，约 8 路（pad/bass/kick/hat/drone） |
| CPU | 音乐调度器 25ms 前瞻；每帧调度量极小 |
| 内存 | 程序化合成 ≈ 0 资源字节；未来采样资产：SFX 短音 ADPCM 等价、音乐流式 Vorbis 等价 |
| 自动播放策略 | 首次 `pointerdown`/`keydown` 解锁 AudioContext |

## 6. 自适应音乐系统

### 6.1 参数架构
| 参数 | 范围 | 来源 | 作用 |
|---|---|---|---|
| `tension` | 0.0–1.0 | `onFight` 由 `diffCfg().enemyMult` 映射（0.72→0.0，1.45→1.0）；boss 强制 1.0 | 控制 combat/boss 层密度、打击亮度、低音厚度 |
| 音乐状态 | exploration / shop / combat / boss / victory / defeat | 各界面切换 / 战斗结果 | 决定激活哪些生成层与速度 |

### 6.2 生成层（Generative Layers）
| 状态 | 速度(BPM) | 激活层 | 说明 |
|---|---|---|---|
| exploration | 96 | bed（pad） | 探索/菜单，可无限循环不疲劳 |
| shop | 104 | bed + 轻脉冲 | 运营期，低紧张度律动 |
| combat | 124 | bed + bass + 脉冲（kick/hat，密度随 tension） | 战斗，tension 驱动 |
| boss | 138 | bed + bass + 脉冲 + drone | 首领，最厚最密 |
| victory / defeat | — | 一次性 stinger（走音乐总线） | 结算终止式，不切断底层 bed |

### 6.3 过渡规则
- 一切状态切换走 **0.8s 交叉淡入**，无硬切（除非设计显式需要）。
- `tension` 变化通过调度器自然体现，无需重配音轨。
- 跳过战斗演出时（`G._audioSkip`）战斗音效整体静音，避免瞬间叠满。

## 7. SFX 设计细则

- **程序化 + 参数化**：每个事件是一段小型合成图（振荡器/噪声 → 滤波 → 包络 → 总线），**每次带随机音高/音量微扰**，保证"没有两次完全相同"。
- **战斗按伤害类型区分**：
  - 物理（`dmgType:'phys'`）：低频冲击 + 噪声撞击。
  - 法术（`dmgType:'arts'`）：带通金属铃音 + 滑音。
- **技能按 archetype 区分音色**：`heal` 微光、`shield` 金属、`buff` 上扬、`def` 下行、`summon` 低频召唤、`burn` 火焰、`cast` 空灵钟声、默认能量脉冲。
- **阵营（side）**：友方/敌方死亡音色微差，强化空间代入。
- **限流**：每战斗帧最多 2 个 hit、2 个 skill 音效，避免拥堵。

## 9. 后续升级路线（当委托真·音频资产时）

引擎 API **保持不变**，只需替换内部实现：
1. **SFX 采样化**：将 `EVENTS` 中各事件的程序化合成替换为 `AudioBufferSourceNode` 加载的采样（短音 ADPCM 等价、UI 用 PCM 零延迟）。事件名与参数接口不动。
2. **音乐分层化**：将生成式 `playPad/playBass/playKick/...` 替换为分轨素材（stem），由同一 `tension`/`state` 参数控制各层增益与交叉淡入——横向重排序优于纵向叠加，更省内存。
3. **空间化（可选）**：2D 自走棋无需 3D 空间化；若做镜头/视差，可对战斗音效加 `StereoPannerNode` 按单位 x 坐标定位。
4. **诊断 HUD**：可加开发期叠加层显示当前语音数、`tension`、音乐状态，便于调参。

- `node --check audio.js` / `game.js` 通过。
- 模拟 `AudioContext` 冒烟测试：遍历全部 28 个事件 + 6 个音乐状态 + 静音/音量/别名，零运行时异常。
